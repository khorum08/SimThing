## BUILD
- **Do not build an inbox — finish the one that exists.** `SimThing.overlays` is already the reception surface, `add_overlay` already the delivery primitive, and `evaluate_node` already folds a node's own overlays onto a `TransformStack` inherited from its ancestors. The gap is ARRIVAL: every construction site hands the overlay to a directly-resolved target (`affects: vec![target]`), flattening the traversal that found it, so no intermediate node ever sees the directive.
- **(a) RECEIVE — three delivery modes, on existing homes.** Deficit-driven rides `owner_silo_disburse_down` / `runtime_local_allocation_from_disbursement` (free, already sweeping). Standing rides the `resolve_owner` inheritance walk (zero storage for inheritors; absence means inherit). Predicate-broadcast is ONE tree walk paid by the initiator — the only mode that does not fall out of RF, so name it as its own and do not disguise it as free.
- **(b) ORIGINATE — `Overlay.origin: SimThingId`, REQUIRED.** This is not new provenance: ~60 construction sites already hold the originating node in scope and discard it. Make an unattributable overlay UNCONSTRUCTIBLE at the type boundary. `OverlaySource` is RETAINED and complementary — origin says WHICH NODE, source says WHAT KIND OF WILL. Scenario-authored overlays originate from the ScenarioThing. Spatial location is DERIVED from origin, never stamped.
- **(c) ROUTE up to the common ancestor then down**, so the overlay stack filters along the path. Direct `affects` targeting is the bypass this rung closes, not a cheaper variant of it.
- **(d) INERT BY DEFAULT.** The `Vec` starts empty; a gridcell that never originates or receives stores nothing — the same zero-cost shape ownership already has.
- **(e) STATE the predicate composition rule; do not inherit it.** `TransformStack` applies `PropertyTransformDelta`s SEQUENTIALLY per matching `property_id`, so a later delta can overwrite an earlier one (`Set` after `Multiply`) — value composition is last-wins-capable. A policy chain needs CONJUNCTIVE composition. Prove what two nested policies mean; restrictions must compose so a descendant cannot loosen an ancestor.
## FENCES
- **Conservation is NOT weakened and the Invariant Set is NOT expanded.** A consumed directive is a resource and conserves; a standing directive is an inherited property, READ not moved, and carries no conservation claim. Reading a value is not moving it.
- **No new transport.** Reduce-up carries perception, disburse-down carries directive; both are built. Each direction runs once per generation and disbursement is depth-banded — a receive→originate→receive cycle is already bounded by tree depth, so no authored cascade bound is admissible.
