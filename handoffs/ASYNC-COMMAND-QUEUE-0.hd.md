- Coalesce pending upward products by the existing canonical `{owner, resource, scope}` bucket key. Every `OwnerChannelRfBucket` quantity field is summed exactly, yielding at most one pending value per distinct bucket. The seam itself is a holding account, so conservation is `child + seam + parent` at every instant, not eventually.
- Extend the existing 6.1 `IntegrationSchedule` as the ONE replay recorder with a row kind for queue/injection integration. Values coalesce; stamps do not: the coalesced carrier exposes newest stamp = `max`, while the recorder preserves the FULL set of contributing child generations per product.

- Make the seam bidirectional. Upward stamped products and the downward ancestor standing/policy view both cross as barrier-refreshed stamped state; cross-site identity is canonical `OwnerRef`, never a session-local interned id. Generation-consistent shadow/snapshot reads are double-buffered/torn-free.

- **Conservation remains instantaneous.** The queue is a holding account; never drop conserved products and never make the parent wait to avoid accounting them.
