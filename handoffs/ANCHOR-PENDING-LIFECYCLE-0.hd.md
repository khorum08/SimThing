## BUILD
- Implement **11.5 `ANCHOR-PENDING-LIFECYCLE-0` only**. This is a harness-lifecycle rung for anchors minted at graduation before canonical prose catches up. It must extend the existing anchor/librarian/closeout authorities; it does not create a new anchor system.
- Add a single `lifecycle` column to `scripts/ci/doctrine_anchors.tsv` with exactly two admitted shapes for this rung: `canonical` and `pending:<RUNG-ID>`. Existing anchors are `canonical`; the two anchors minted with the 11.4 stamp are `pending:UNIFIED-INGRESS-EXCLUSIVITY-0`.
- The lifecycle classification joins explicit pending rows to existing ladder machine truth:
  - `PENDING-HEALTHY`: minting rung is graduated and its canonization consumer has not yet closed the pending set. Advisory inventory only; never an ordinary gate failure.
  - `ORPHANED`: minting rung is absent/reverted/remedial-superseded under existing machine truth. It is reap-eligible, not silently deleted.
  - `STALE-PENDING`: the canonization consumer is live/graduated but the interim row was not repointed to canonical prose. This is a failure requiring repair, not automatic deletion.
- Extend `anchor_query.sh` / `anchor_check.sh` only as needed to parse, validate, report, selftest, and hash-check the widened schema. Existing canonical query semantics, narrow trigger routing, reach-log appends, dead-listener/prune behavior, and anchor hash integrity must stay green.
- Extend the existing `librarian.sh` with `--pending-anchors [--confirm]` (or the repo's equivalent existing CLI convention) and extend the existing `/librarian` parser in `doctrine_exec_commands.sh` so `/librarian pending-anchors` lists dispositions and `/librarian pending-anchors --confirm` reaps ORPHANED rows only. Reuse the existing doctrine-exec librarian job; do not add a second workflow or mutation door.
- Confirmed reap writes exactly one provenance record to the existing `authorized_deletions.tsv` per removed anchor. Archaeology its current schema and consumers before choosing a representation. If that ledger is mechanically incapable of representing anchor deletion safely under existing consumers, STOP and return the exact conflict rather than silently widening/overloading it.
- Extend `track_closeout.sh` so track closeout asserts **zero `pending:*` rows**. A pending row must have been repointed to a canonical in-tree doc section or reaped with explicit deletion provenance before closeout can pass.
- Keep the two live pending anchors narrow: `unified-ingress-exclusivity` remains scoped to ingress/exclusivity/consumer/census/resolution/proof/deferral vocabulary; `stemthing-b-market-grammar` remains scoped to grant/disbursement/granting/grantee/draw/clearing/flow-market/conserved-resource/grant-lifecycle vocabulary. - Anchor targets remain in-tree document sections only. 12.2 will later consume the pending set as the canonization repoint worklist; this rung must not author or anticipate 12.2 prose.
- Keep pointer at 11.5 in coding. Return PROBATION / proof-present / DA-review-pending; no self-graduation or merge.

## FENCES
- **Explicit lifecycle, not inference.** `pending:<RUNG-ID>` is declared data. Do not infer pending/proof status from names, reach logs, timestamps, or call-like relationships.
- **One anchor authority.** `doctrine_anchors.tsv` + existing query/check machinery remain the source of truth. No sibling lifecycle table/checker.
- **Healthy pending is lawful.** `PENDING-HEALTHY` is visible inventory and cannot make an ordinary mid-track anchor check fail.
- **Reap is explicit and confirmed.** Dry-run/listing never mutates. Confirmed reap removes only ORPHANED rows and records one deletion-provenance entry per row.
- **Stale pending is not reap-by-default.** A canonization-complete-but-unrepointed anchor is a repair failure, not an orphan.
- **No external anchor targets.** PR/Board comments are evidence, never doctrine targets.
- **No trigger-domain inflation.** Lifecycle metadata must not broaden anchor reach or coding ACK burden.
- No crate/source/runtime changes. Do not touch 12.1, 12.2 canonization content, Vector CostBand, the ClauseThing baseline reds, or graduated 11.4 semantics.
