- Consume `OwnerChannelScopeKey` segregation exactly as landed. The clearing surface receives already-separated owner/resource/scope buckets and never re-derives or compares owner identity.
- Make the clearing law authored data. Priority consumes the existing `CommandDeficit` -> `RuntimeOwnerSiloDemandBucket` priority field; price pressure consumes the existing order-weight semantics rather than minting a price-clearing service.
- Keep unresolved quantity `U` distinct from CostBand remainder `R`. Clearing produces allocation plus unresolved demand; CostBand separately quantizes granted/held value into executable depth and remainder.
- Factor attrition/adversarial persistence temporally, not as a peer clearing identity: unresolved `U` is ordinary observation/field input; authored EML values continued commitment; CostBand funds any consequence; ordinary state/claim changes appear only in a later generation. No clear-persist-reclear loop exists inside one generation.
- Express clearing/persistence outcomes through ordinary overlays using `UntilDissolved` with authored dissolution conditions. Explicit removal remains ordinary. Do not reintroduce `Permanent`/`Never` semantics.
