## BUILD
- Formalize the existing SimThing embedding surface as exactly five verbs: **Derive, Populate, Overlay, Bind, Run**. Keep the surface human-readable and scale-invariant; one SimThing and a tree of thousands use the same verbs.
- Prefer a thin stateless vendoring facade only where it makes the existing mechanisms legible. Every verb must bottom out in already-graduated admission/session/kernel mechanisms; the facade owns no simulation state or authority.
- Derive carries specialist/owner-seat data; Populate builds/adopts the tree, binds inherited ownership, and declares queue shape; Overlay requires authored origin+horizon; Bind exposes sealed event bindings plus read-only generation-coherent shadow observation; Run selects paced|continuous posture over one kernel and one replay history.
## FENCES
- This rung is interface formalization, not implementation of new simulation capability. No guide/exemplars (11.2), convergence witness (11.3), portability proof/canonization (12.x), StemThing-B, Vector CostBand, or ClauseThing debt repair.
- ClauseThing may be demonstrated as one front-end only if needed to prove containment; do not reshape core around ClauseThing or any domain.
