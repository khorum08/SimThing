## 1. Recommendation and intended result

Open **one product-led refinement track with several interleaved PR ladders**. Build a reusable, native ClauseScript economy scenario through the ordinary ClauseThing → scenario admission → resident SimSession → Studio path, and use that same scenario as the integrated workload throughout the performance campaign. Author the hierarchy for the game model, not for GPU packing, uniform fanout, locality, or dispatch efficiency. Keep small synthetic workloads for isolating costs and proving platform invariants. Neither workload substitutes for the other.

The track delivers three things together:

1. A portable `scenarios/stellaristhing_base.clause`: a maintained authoring foundation in which two factions produce resources, fund construction, create and sustain fleets, move them toward authored destinations, and resolve opposing damage against HP. Future StellarisThing adaptations change authored definitions and policy, not engine branches.
2. A modernized ClauseThing/scenario/Studio vertical that reliably loads, admits, executes, observes, saves, restores, and diagnoses that content through the unified SimThing and RF Triad.
3. A completed performance research campaign: current instruments, reproducible application measurements, and adjudicated results for every inherited research path. It first explains the natural constraints of the representative hierarchy. Kernel layout and algorithm optimizations form a later, explicitly released ladder, evaluated against that unchanged authored model.

**The integration criterion is a living economy in the current Studio client.** A parsed file, a displayed map, pre-seeded fleets, a passing kernel benchmark, or a separate headless economy does not independently satisfy that criterion. The first visible slice arrives early and grows throughout the track; Studio integration is not a final-phase surprise.

## 3. Product contract: the reusable economy asset

### 3.1 Authoring foundation

`stellaristhing_base.clause` is the single operator entry point and the maintained source for the demonstration. It contains a working default two-faction configuration plus documented seams for resource definitions, recipes, faction policies, fleet templates, topology, initial endowments, seed, and scale. Prefer ordinary existing variables, expansion, and includes where they express those seams; any missing syntax belongs in the compiler capability audit before it is promised.

The preferred distribution is self-contained. If a map or shared definition genuinely needs an auxiliary asset, the file opens directly from a portable, versioned bundle with relative paths, content identities, and an explicit dependency manifest. No private corpus path, machine-specific resolver token, manual JSON patch, or Rust scenario builder is required. Generated JSON is a reproducible interchange/cache product, not an independently edited economic source. Changing process working directory must not change source resolution.

The file is a base for future StellarisThing iteration, not a claim to implement all Stellaris scripting. Publish the supported constructs and their semantics; reject unsupported executable constructs with useful source provenance. Inert presentation metadata is explicitly distinguished from executable declarations. A modifier or recipe that parses but vanishes during lowering is a product failure.

### 3.2 Small, causally complete economy

The initial content is deliberately bounded so its economics can be inspected:

| Authored element | Required behavior |
|---|---|
| Two distinct faction identities | Both use the same entity/recipe mechanisms; differences come from endowments and admitted policy. Ownership and spatial containment remain separate. The engine never branches on faction identity or on there being exactly two factions. |
| Spatial hierarchy | A connected, uneven application hierarchy with sources, processing locations, shipyards, and fleet hosts. The workload exercises at least three parent-child RF edges and a spatial bottleneck; it must not silently flatten or rebalance the hierarchy to make admission or execution cheaper. |
| Resource chain | Suggested initial vocabulary: energy, minerals, and alloys. Extraction feeds processing; processing feeds construction; completed fleets consume upkeep. Resource-specific conversion coefficients, sources, sinks, caps, and holding accounts are authored and accounted for explicitly. |
| Construction demand | Fleet production competes with maintenance/processing for finite inputs and capacity. A Draw authorizes demand; requests and priority do not themselves reserve stock. Explicit commitments account for resources in flight. |
| Funded completion | CostBand funding and the existing actuation/boundary path create actual fleet/ship SimThings with ownership and location. Numerical funding precedes structural placement; no UI timer or scripted spawn schedule supplies the result. |
| Scarcity and recovery | Reduced input or increased impedance changes serviceable flow, allocation, unresolved demand, and completion timing. Restoring supply permits recovery through ordinary execution. Persistent shortfall uses the once-mint `authored + f(U)` path. |
| Policy variation | A supported authored modifier chain alters allocation or persistence through admitted EML. A policy change must be observable without changing source code. Policy admission and runtime activation use their existing distinct doors. |

**Do not assume multi-resource construction or runtime fleet assembly is already fully exposed by hydration.** Phase 0 traces each requirement to an admitted producer, consumer, and lifecycle. A missing authoring binding is a ClauseThing/spec-boundary task; a missing generic capability receives a narrowly reviewed capability rung with a synthetic witness. Neither omission may be hidden with an offline fleet seed or a domain-specific construction manager.

Multi-resource completion must not spend one input irreversibly and then discover another is missing. Define its reservation, completion, cancellation, placement-refusal, and release behavior through existing commitment/CostBand/boundary semantics, or resolve the precise generic gap before implementation. Resource conversion is not conservation of unlike units: accounting checks each lane and its admitted source/sink/recipe coefficients.

### 3.3 Natural hierarchy and application-scale growth

Choose the semantic containment appropriate to the application: galaxy/spatial regions, systems, planets or sites, production facilities, and fleets with ship/cohort children, expressed through the admitted SimThing vocabulary. Some systems are sparse, some have several inhabited sites, and industrial centers concentrate facilities, claims, and fleet activity. Owners remain policy/identity relations rather than convenient spatial grouping containers. Uneven depth, fanout, resource mix, policy inheritance, and growth are expected workload properties.

Begin with a small version of that model for inspection, then increase authored application parameters while retaining its structure and distributions. Add systems, develop more sites, expand industry, and build fleets through actual simulation behavior. Record the resulting participant counts, pressure hotspots, depth, churn, memory, and timing. Distinguish content-generated workload from synthetic stress injection.

Do not group facilities into invented containers to balance a reduction, reorder the authored hierarchy for coalescing, pack every system to a preferred tile size, cap population at the measured fast point, preallocate completed fleets, or choose only low-contention recipes. Existing admitted physical lowering still runs normally; this proposal does not undo it or force an inefficient physical layout. It defers new packing, reordering, segmentation, tiling, compaction, and scheduling optimizations while application behavior is established and measured.

The initial performance report should locate the practical constraint surface: load/admission cost, the point generation time grows sharply, which natural subtrees accumulate pressure or unresolved demand, when observation falls behind, and what lawful resource/residency limits bind. Report those boundaries instead of shrinking or reshaping the reference scenario until it appears fast. A later optimized implementation must run the same authored model and preserve its economic meaning.

### 3.4 Proposed named product acceptance

At track commitment, record **ECONOMY-TO-FLEET-ACCEPTANCE** as the specific Owner/DA product criterion, separate from the platform's generic correctness invariants:

- Under the admitted default profile, both factions complete new funded fleets after generation zero within a declared finite observation horizon. Starting fleets, if useful for context, do not count as completions.
- With an essential construction input absent and initial convertible stock controlled, new completion stops. With supply restored through admitted input/policy, completion resumes. No unbacked stock or duplicate completion appears.
- A capacity/impedance change and an authored policy variant each produce an attributable change in born state and economic outcomes. Fleet counts need not follow a predetermined cinematic script.
- The created fleets enter the ongoing economy: upkeep and capacity consumption remain visible after birth, save/restore, and subsequent generations.
- A second configuration changes faction labels, recipe coefficients, policy, and map/scale data without engine edits or a second scenario builder. This establishes the reuse seam; it does not assert universal language coverage.

Freeze the profiles, seed set, horizon, expected qualitative relationships, and necessary quantitative bounds before evaluating this criterion. An inert but mathematically valid economy fails this named product acceptance. It does not justify inventing a generic emergence invariant or fitting the kernel to a desired story.

These roles are not interchangeable. A local scalar operation can use a degenerate route or no capacity-bearing transport binding; do not invent artificial geometry or a second flux calculation just to make every diagram contain three nontrivial legs.

### 3.6 Movement: pay impedance with generated movement work

**Owner model, made precise:** the destination is the ActionBand target, and PALMA at the subject's current locus supplies the remaining impedance to that target. Movement points are the authored resource/work unit that pays this impedance. Spending them advances the subject proportionally to *local paid work*, rather than to straight-line separation or a fraction of a freshly recomputed whole-route estimate.

For an admitted topology, the conceptual destination-seeded potential is:

```text
D_N(destination) = 0
D_N(v) = min over admitted neighbors u of [w_N(v,u) + D_N(u)]
```

This is the min-plus field's cost-to-go interpretation: accumulated impedance along a lawful route is represented by local field values. It is not a host walk summing nodes, a saved node sequence, or a predecessor table. The actual implementation consumes the existing bounded PALMA sweep and its admission/freshness conditions. A finite-horizon value is not automatically a globally converged shortest-path result; unavailable, out-of-horizon, ambiguous, or unreachable targets produce the admitted refusal/stall state rather than fabricated distance. Node impedance must be assigned to edges consistently so a node is not charged twice.

Proposed per-generation lifecycle:

1. A directive/standing policy activates an admitted `LocusRadius` or `PalmaReachableSet` target. The subject keeps stable logical identity; raw destination ids are not coordinates to subtract. Arrival is the target's admitted satisfaction predicate.
2. Propulsion capability and funded fuel/energy/upkeep generate movement work through an authored recipe. The rate, units, cap, and unspent-point retention/expiry are explicit. V1 should use a bounded balance with an authored expiry policy, not unlimited banking by omission.
3. Consume the born PALMA potential to select a lawful adjacent descent. For capacity-bearing travel, consume already-resolved Gu-Yang/RF transit throughput exactly once. A new `min(capacity, speed)` side calculation must not re-clear native throughput. If the admitted topology genuinely has no scarce transit channel, that binding degenerates out.
4. CostBand spends admitted movement-work quanta against the current transition's impedance. For constant positive local cost `c` per unit progress, `delta_progress = spent_work / c`, bounded by the remaining local transition. If cost varies along the transition, use its authored piecewise accumulation; do not reuse a single cost for untraversed terrain. Exact spending/ownership and admitted numerical rounding remain separate, preserved contracts.
5. At the local completion crossing, ActionBand emits the existing sealed adjacent structural transition. CPU placement applies that result without selecting direction or recomputing movement. The next generation consumes the newly bound location and field. There is no hidden multi-hop path executor; the existing one-local-step ingress bound is preserved unless separately amended.
6. Arrival terminates the target lifecycle. Retarget, blockage, topology change, destruction, and placement refusal each have an explicit release/retention disposition for any paid local work or committed resource. Rebind invalidates stale field/target bindings. Price changes do not create free progress or spend the same work twice.

Partial progress is an ordinary admitted property/band value if such a binding exists; it does not prematurely change the subject's structural cell. Studio may interpolate along the selected local transition for display while showing the committed locus and progress separately. If the required fractional-progress binding is missing, name that generic authoring/admission gap rather than adding a movement-owned history or position authority. A scalar CostBand remainder stays resource remainder, not RF unresolved carry.

**Illustrative witness:** two successive adjacent transitions cost 3 and 4 movement-work units, and propulsion produces 2 per generation with bounded remainder retention. The first transition completes on generation 2, leaving 1 unit; the second completes on generation 4, leaving 1 unit before the authored arrival disposition. Cost-to-go begins at 7; structural movement occurs only on funded local crossings. This example is an accounting target for the proposed binding, not a claim of an already available API. A changing PALMA field may change the remaining estimate; it cannot retrospectively alter what was paid.

Required failures include free movement with zero funding; crossing a blocked/unreachable edge; charging total `D_N` repeatedly; decrementing a target deficit solely because the field changed; spending transit capacity twice; teleporting by Euclidean interpolation; and silently choosing an ambiguous neighbor by physical row order. Fuel exhaustion, opposing transit pressure, target changes, and fleet growth should be natural performance/behavior probes, not removed to produce a clean benchmark.

### 3.7 Combat: opposing damage serves an HP-to-zero target

**Owner model, made precise:** from the attacker's perspective, the target is `hp <= 0` and remaining HP is the depletion workload. The defender does not author a desire to die or voluntarily offer its HP to an enemy allocator. Hostile eligibility and the permitted property effect are established by the admitted attacker/target relation. Friendly repair is a distinct positive-flow use of the same property.

The proposed first combat slice uses finite per-generation weapon output, explicit eligibility, and aggregate target resolution:

1. Weapon/ship capabilities and paid operating inputs produce a bounded damage resource. Authored modifiers may shape that output through EML. Range, hostility, permitted targets, and any occlusion/reach conditions compile into bounded bindings; no CPU combat loop searches the world for targets.
2. An admitted ActionBand target or target set directs eligible damage toward opposing HP. PALMA/STEAD supply the relevant spatial reach and pressure information. Gu-Yang/RF constrains delivery where there is a real capacity-bearing interaction; a direct already-local hit does not need an invented transport field.
3. The ordinary allocation/transfer path shares each source's finite output among eligible targets and aggregates deliveries per target. One emitted damage unit cannot be fully applied to several targets. Apply effectiveness/armor/shield deformation once at its declared producer or receiver stage; V1 can use direct hull damage, leaving layered defenses as authored follow-ons.
4. Apply the admitted depletion transfer to the target's HP. In target-HP units, let `A` be total **applied** damage and `R` funded repair for the generation: `H_next = clamp(H_current - A + R, 0, H_max)`. All quantities come from the same declared generation contract. Bound applied damage by the permitted target depletion; expose excess emitted/unapplied damage as an explicit expiry or other authored disposition, not a second loss of HP.
5. Use a simultaneous-Current proposal for V1: combatants alive in sealed Current may emit their funded attacks; aggregate effects resolve under one declared order before the terminal crossing. A unit killed during that resolution does not retroactively cancel an already emitted attack. Repair ordering/caps and whether repair can avert removal must be authored and frozen before the witness; physical dispatch order cannot decide them.
6. The existing HP-zero crossing emits one casualty/removal consequence through `BoundaryRequest`. Release capacity/commitments and terminate affected streams through the graduated membership lifecycle. Ownership remains attribution; death is not a special combat allocator or a separate entity-deletion route.

**Avoid a second HP debt.** For the proposed V1, read the authoritative current HP as the per-generation depletion bound and make the attack-service claim generation-local with an admitted zero carry deformation (`f(U)=0`). Remaining HP already represents work still to do next generation. It must not be re-authored in full *and* receive yesterday's unresolved quantity. Likewise, unused weapon output expires unless an explicit ammunition/storage lane owns it. If the existing HP transfer door needs no separate demand product, reuse that simpler shape rather than minting one for the diagram. Any continuing attack-intent state remains an ActionBand lifecycle, not duplicated economic HP.

**Illustrative witness:** two funded attackers emit 4 and 3 damage units toward a target with 6 HP and no mitigation/repair. At most 6 units are applied, HP reaches zero once, and the remaining emitted unit has the declared unapplied disposition. The target is removed once. Swapping physical attacker order cannot change the canonical result; any contributor attribution follows existing exact tie/ordering law. A simultaneous exchange may destroy both parties under the proposed Current-based rule.

Required failures include damage without a funded/live source, friendly fire outside the admitted policy, duplicated area damage, repeated HP subtraction through both field and consumer, overkill creating negative stock, carried “ghost damage” after target departure, and a killed unit producing later-generation attacks. Damage/repair/casualty must survive ordinary observation, checkpoint/restore, remap, and multi-tree identity tests. Damage is an admitted source/sink/transfer relation; do not claim that attacker energy and defender HP are conserved in one unit merely because both use RF.

### 3.8 Decision-space economics — keep the possibility open

**Exploratory horizon, not an immediate closeout requirement.** The promising direction is to make an unresolved strategic condition generate competing, resource-funded ways of changing that condition. The “path” is a realized sequence of target-discrepancy reductions through pre-admitted ActionBand/recipe bindings. It is not necessarily a spatial route, a universal planning graph, or a promise to discover arbitrary strategies.

For example, define an authored border-risk discrepancy from comparable born observations at locus `z`:

```text
risk_z = max(0, perceived_hostile_pressure_z - effective_friendly_coverage_z)
```

The common pressure unit, capability weights, range, perception, and confidence are authored assumptions. Scalar equality is not proof of tactical safety. Coverage does not become a conserved resource, and a UI estimate never writes true HP, strength, or ownership. Hierarchical reductions expose where pressure exists without host descendant scans.

| Response family | How it can reduce the discrepancy | Ordinary scarce inputs and time | Lawful realization |
|---|---|---|---|
| Deploy existing ships | Increase effective friendly coverage at the threatened location; coverage may fall where those ships leave. | Travel work, transit/supply capacity, upkeep, opportunity cost of withdrawing defense elsewhere. | Existing movement target and subsequent presence observations. A departure or issued order does not count as arrival. |
| Engage the enemy | Reduce hostile pressure by depleting enemy HP/capability. | Reachable fleet capacity, weapon inputs, exposure to damage, ongoing supply. | Existing combat effects change actual enemy state; speculative expected kills are not credited as realized relief. |
| Build fortifications | Increase stationary defensive coverage/capacity after completion. | Materials, work, residency, location, build delay, subsequent upkeep. | Existing construction grammar produces an admitted defensive instance; its born state supplies coverage. |
| Build/reinforce fleets | Create movable future coverage and enable later deployment/combat. | Construction inputs, delay, crew/capacity if authored, and upkeep. | Existing fleet-birth requirement activates movement/engagement only through admitted dependencies. |

These are complementary as well as competing responses. Finite authored EML can turn risk, capability, travel potential, delays, costs, and current commitments into eligibility and allocation-weight deformation for pre-admitted response bindings. RF allocates the real resource lanes; explicit commitments reserve them; native fields constrain realization. A candidate's desirability score neither creates resources nor becomes hard precedence by accident. Different currencies remain separate resource constraints, even when a policy compares their authored utility estimates.

Parent unresolved pressure can activate subordinate requirements such as “obtain construction inputs,” “complete a fleet,” or “reach the border.” Their resulting world changes feed later-generation observations. This reuses recursive ActionBands and the one RF filter; no `next_step` scheduler, CPU strategic planner, same-generation convergence loop, or new economic solver is implied. Admitted binding selection can permit a mix of defenses rather than forcing a single winning strategy.

The difficult questions remain visible: avoid assigning the same fleet to incompatible destinations; reserve actual resources without claiming future coverage as present relief; represent build/travel delay; avoid double-counting the same capability under deployment and attack; respond to changed enemy behavior; and prevent churn or oscillating orders. Bounded persistence, commitment lifecycles, authored switching costs, and generation-paced feedback are candidates to test through existing ports, not guaranteed cures. Partial information uses the observer's admitted perception fields, not omniscient host queries.

If this horizon is opened, first run a contained probe with the same border pressure and only three admitted responses: deploy, engage, fortify. Vary travel impedance, material scarcity, weapon effectiveness, and construction delay while holding policy programs fixed. Observe whether resource-feasible response mixtures change and whether **actual later** border pressure falls. Record overshoot, oscillation, stranded commitments, and failure to find a response. No optimal-planning or global convergence claim is justified by a favorable trace. Keep richer predictive models, learning, arbitrary action synthesis, and semantic path-search outside the probe unless separately proposed.

### 3.9 System contracts that must precede coding handoffs

For each required row in §3.5, the workplan records: target form and source; authoritative current state; resource units and production; eligibility/precedence; PALMA/Gu-Yang bindings or justified degeneracy; exact versus continuous quantities; spending/commitment/carry/expiry; effect and structural boundary; departure/retarget/fault behavior; source-to-installed provenance; Studio observables; and a discriminating positive/negative witness. Missing bindings become named generic gaps, not scenario shims.

Add **MOBILITY-COMBAT-ACCEPTANCE** alongside the economy criterion: newly funded fleets move toward authored opposing destinations through paid local transitions, eligible weapons apply finite damage, HP depletion yields a single lawful casualty, and surviving fleets continue upkeep. The Studio shows movement work/cost-to-go/stall and damage/HP/casualty provenance for the same ordinary session. Zero propulsion funding, blocked reach, ineligible targets, and zero weapon funding are meaningful negative cases. Strategic response selection and fortification remain horizon work; movement and combat themselves are required.

## 4. The modernization path

The intended dependency direction is:

```text
ClauseScript source + declared dependencies + authored profile
  → existing parse/expand/hydrate front end, with source provenance
  → canonical admitted spec, programs, topology, and observation bindings
  → ordinary resident SimSession and its one RF/Triad execution history
  → bounded born-state observations and structural boundary products
  → current Studio presentation, persistence, and performance capture
```

Stages here are conceptual responsibilities, not a request for a second IR, registry, or compiler framework. Reuse the existing raw model, hydrated types, admission vocabulary, and expression registry. Introduce a representation only where the audit proves a missing contract and identifies its sole owner.

| Seam to harden | Required convergence / refusal behavior |

## 8. Proof strategy and review gates

Maintain three explicit evidence classes:

1. **Platform correctness:** existing closed invariants, type seals, admitted numeric parity, deterministic replay, identity, containment, and refusal contracts. Extend existing synthetic proofs only for a real uncovered invariant or escaped defect. Preserve explicitly frozen referees; adjudicate a superseded contract at equal or greater strength instead of silently weakening it.
2. **Product acceptance:** the named economy-to-fleet and Studio workflows, using the authored asset and run evidence in the application/workshop acceptance layer. These can gate this track without becoming reusable kernel invariants.
3. **Performance research:** comparable raw measurements and conclusions for the complete declared manifest. Measurements do not replace semantic proof, and generic correctness does not certify responsiveness.

Before a semantic/authority repair, run the falsifier that exposes the defect. Before an optimization, show the baseline bottleneck and state the equivalence obligation. Preserve the discriminating cross-products: live allocation plus exact cap collision plus real temporal carry; generation fault after economic effects; membership changes with recorded termination facts; rebind under changed topology; and restored Studio observation of those same outcomes. Isolated green tests for each component are insufficient when the failure can lie in their composition.

Kernel/generic tests use synthetic content within the owning crate. The shipped asset is durable authored content; no engine dependency, generated orientation inventory, or generic proof asserts that this particular file exists. Temporary experiments stay in the contained workshop leaf with dated disposition. Application-level acceptance can consume the asset through production APIs and is clearly labeled as such.

Any touched adapter-sealed semantic bundle follows the existing E8 pin-roll and clean-checkout reproducibility procedure. Both bound resident and explicit CPU-oracle postures preserve one admitted verdict; do not revive legacy score authority. Run the applicable CPU/interpreted/JIT proofs on qualified adapters, including exact EXP/LN/consumer semantics where touched. Hosted green does not substitute for owner-local GPU/Studio evidence; skipped legs are visible and cannot satisfy a required row.

For routine PRs, use touched-crate checks, delta scan, and the meaningful focused proofs. Structural graduations and final closeout carry the required zero-red certificate and real-adapter evidence under the existing process. Do not multiply full-suite runs or introduce a new proof framework for each ladder. A report identifies what actually ran, its tested revision, and any unsupported envelope.
